# Upload the three showpiece videos into README.md

**Temporary.** Delete this file once the three videos are embedded and the README renders on
GitHub. It is an operational runbook, not archaeology.

## Why it is manual

The MP4s are projections (`decision:1`): generated media, ignored by Git, never committed. There is
no Git LFS here and no proven convention for pushing large media through `gh`. GitHub's own
Markdown editor accepts a dropped video file, uploads it, and mints a hosted
`user-attachments` URL — which is the one place a repository can carry a video without the video
being in the repository. So the upload is done by hand, once, in the browser.

## Render the three artifacts first

They are gitignored, so a fresh clone will not have them. From the repository root:

```bash
npm run render -- examples/observatory.yaml  -o out/observatory.mp4
npm run render -- examples/cathedral-v2.yaml -o out/cathedral-v2.mp4
npm run render -- examples/cuecraft.yaml     -o out/cuecraft.mp4
```

Each takes about a minute on an M-series Mac. Verify all three before uploading:

```bash
ls -la out/observatory.mp4 out/cathedral-v2.mp4 out/cuecraft.mp4
```

Expected, as of this round:

| placeholder in README.md             | local file             | duration | approx. size |
| ------------------------------------ | ---------------------- | -------- | ------------ |
| `<!-- VIDEO: observatory -->`        | `out/observatory.mp4`  | 1:17.6   | ~17 MB       |
| `<!-- VIDEO: cathedral-v2 -->`       | `out/cathedral-v2.mp4` | 1:09.4   | ~18 MB       |
| `<!-- VIDEO: cuecraft-self-demo -->` | `out/cuecraft.mp4`     | 1:45.3   | ~8 MB        |

All three are well under GitHub's per-file attachment limit (10 MB for most file types, but **100
MB for video**, which is the limit that applies here). If an upload is rejected on size, that is
the number to check first.

## The upload, one video at a time

1. Open `README.md` on GitHub: `https://github.com/<owner>/cuecraft/blob/main/README.md`.
2. Click the **pencil / Edit** button (top right of the file view).
3. Make sure you are on the **Edit** tab rather than **Preview**.
4. Find the first placeholder pair:

   ```
   <!-- VIDEO: observatory -->
   <!-- Paste GitHub-uploaded video markdown here -->
   ```

5. Put the cursor on the blank line just below them, then **drag `out/observatory.mp4` from Finder
   onto the editor** — or use the attach-files control at the bottom of the editing area if the
   editor shows one.
6. Wait for the upload to finish. GitHub inserts a line of its own referencing a
   `https://github.com/user-attachments/assets/...` URL. **Do not type this URL by hand and do not
   guess it** — it only exists once the upload completes.
7. Delete the two placeholder comment lines, leaving GitHub's inserted line in their place.
8. Repeat steps 4–7 for:
   - `<!-- VIDEO: cathedral-v2 -->` → `out/cathedral-v2.mp4`
   - `<!-- VIDEO: cuecraft-self-demo -->` → `out/cuecraft.mp4`
9. Switch to the **Preview** tab. Each of the three sections should show a video player, in this
   order: Observatory, Cathedral v2, Self-demo.
10. **Commit changes** — commit directly to `main`, with a message such as
    `Attach the three showpiece videos to the README`.
11. Pull the commit back down locally so the working tree does not diverge:

    ```bash
    git pull --ff-only
    ```

## If GitHub's UI differs from the above

This is written against GitHub's web editor as it behaved when the round was packaged, and GitHub
moves its buttons. The steps that are _durable_ are:

- the video must be uploaded through a GitHub editing surface, so that GitHub hosts it;
- the resulting `user-attachments` URL is generated by that upload and cannot be predicted;
- the placeholder comments mark exactly where each generated line belongs.

If the drag-and-drop target, the attach control, or the tab labels have moved, follow whatever the
current UI offers for attaching a file to Markdown — the outcome is the same. Do not work around a
missing control by committing the MP4 to the repository, adding Git LFS, or pushing the media
through `gh`; none of those are conventions this repository has.

## Sanity check afterwards

```bash
git pull --ff-only
grep -n "VIDEO:" README.md        # should print nothing
grep -c "user-attachments" README.md   # should print 3
git status --short                # should be clean
```

Then delete this file and commit the deletion.
