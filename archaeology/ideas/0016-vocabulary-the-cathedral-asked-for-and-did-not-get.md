# Vocabulary the cathedral asked for and did not get

## Problem

Building one world surfaced five pieces of vocabulary the artifact clearly *wanted*, and shipping
any of them would have been shipping a graph description language on the strength of a single
example. They are recorded here so the pressure is visible the next time a world is written, and
so nobody re-derives them from scratch and assumes they are new.

## Sketch

In descending order of how hard each one pushed:

**`group`** — the cathedral has two lanes, a narration lane and a content lane, and it says so
nowhere. dagre found them because the relations imply them, which is the good outcome; a world
whose lanes were not implied would have no way to say so. This is the one most likely to be
genuinely semantic rather than geometric, and it is also one keystroke from being a layout hint.

**`kind`** — a stable colour identity per semantic category (source / time / compiler state /
output). Deliberately not exposed: colour is currently derived from position along the flow, which
for a transformation is the same information and costs no vocabulary. A world that is *not* a
transformation would have nothing to derive from.

**Labelled relations** — "feeds", "measures", "chooses". Every one of the cathedral's thirteen
relations means something slightly different and all thirteen are drawn identically. It reads
fine. It reads fine because the entity labels carry the meaning, which may not survive a world
where they do not.

**`focus` / `path`** — naming a traversal explicitly, rather than deriving it from which cues
activate what. This one is the trap: it is a camera instruction with a semantic costume on, and
the derived version is strictly better because it cannot go out of step with the narration.

**A recursive terminal.** The entity nothing leaves is already found by the compiler. A first cut
rendered a live miniature of the whole world inside it, and at the scales that plate actually
appears at, an eleven-node schematic is indistinguishable from a compression artifact. The idea is
right and the scale is wrong; it would want a plate sized for it, which is geometry.

## Boundaries

None of these should be added because it would be nice to have. The rule from decision:10 applies
unchanged: an archetype — or here, a key — is added when a real artifact looked wrong without it,
and the correct response to a layout problem is usually to change the world rather than to
describe it harder.

The related pressure that is *not* about worlds: decision:23's recalibration is scoped to the
atlas, and the other seven archetypes still read `established` as a third colour. Propagating it
is a small change with a large blast radius across the existing deck, and wants its own round.

## Evidence

`examples/cathedral.yaml`, and the fact that it needed none of the above to be legible. See
decision:22 for what was built and dragon:8 for whether any of it should have been.
