# Take the evidence back as data, and let the artifact carry its own names

## Goal

Let a foreign program hand back **structured data** rather than a picture, and let cuecraft
materialize that data into an exhibit whose rows narration can address by name — including a row
that is not currently on screen, which the exhibit brings into view itself.

And, beside it, find out whether an R-drawn **SVG** can carry semantic identities *inside* the
artifact, so that narration reaches an element rather than a rectangle drawn over one.

## Rationale

sprint:25 established that a slide can be evidence a foreign program computed. sprint:26 and
sprint:27 established that narration can reach *into* that evidence, by rectangle, and that the
emphasis is occupancy rather than heat. All three rounds share one shape: **R draws pixels, and
cuecraft draws over them.** cuecraft has still never read anything R produced.

Two questions follow, and they are opposite halves of the same thesis.

**Can the artifact carry its own meaning?** decision:57's spike found base R's `svg()` emits no
`id`, no grouping and no `<text>`, which is why regions exist at all. That is a fact about the
*device*, not about R: a program that knows which object it drew can rewrite its own output before
declaring it. If it can, the identity travels inside the picture, cuecraft discovers it rather than
being told a rectangle, and the emphasis stops being a veil over everything else and becomes a
change to the thing itself. That is also the first exhibit that can return **exactly** to the state
it was imported in, which regions never had to answer because a veil has nothing to restore.

**Can the artifact be data rather than a picture?** Everything decision:55 refuses is about
*pixels* — a stale image, a checked-in asset, a composition cuecraft cannot read. None of those
objections apply to a CSV that R computed on this run. And a CSV is something cuecraft *can* read,
so for the first time an exhibit's content could be laid out by cuecraft, with its own type, its own
palette, and its own activation — while still being evidence cuecraft did not compute and could not
have. The row identities would be the first identities in this format **derived from data** rather
than authored or generated by the compiler.

The interesting behaviour is the one that is not merely emphasis. A table with more rows than fit
has a viewport, and `activates: row-west` means *pay attention to West*, not *scroll and then
highlight*. The exhibit owning the mechanics required to satisfy a semantic intent is the thing this
round is actually testing.

## Success criteria

- `#cuecraft output csv <name> <file>` is a type the runner accepts, validated to the bytes, with
  the same containment, existence, non-empty and diagnostic guarantees `png` already has. Tested
  without R installed.
- `#cuecraft output svg <name> <file>` likewise, and the semantic identities inside it are
  **discovered from the file** rather than declared beside it.
- A deck's `activates:` reaches a named element of an R-drawn SVG, and the element returns to
  **exactly** its imported styling when narration moves on. Sequential and partially overlapping
  attention both leave ground state intact, and an element that stays attended across two sentences
  does not flash through ground between them.
- A slide whose program declares a CSV renders as a table cuecraft laid out — measured columns,
  bounded viewport, deliberate overflow — with row identities generated from the data.
- `activates:` on a row that is **outside the visible viewport** moves the viewport to reveal it and
  then emphasizes it, deterministically, with no authored scroll instruction anywhere.
- The showcase renders end to end: raw transactions CSV → R groups, aggregates and pivots → derived
  CSV → cuecraft table → narration focuses rows. Judged on the film.
- `npm run check`, `npm run test:r` and `scarp doctor` pass.

## Non-goals

- **No selector syntax.** `activates:` addresses an identity and will not learn `#id=`, a predicate,
  a CSS selector, a column expression, or anything else that is a query. If a row cannot be reached
  by name it cannot be reached.
- **No spreadsheet.** No sorting, no filtering, no editing, no conditional formatting, no pagination
  framework, no virtual scrolling, no interaction of any kind. A table here is a *readout*.
- **No dataframe abstraction.** cuecraft parses a CSV into strings and does not acquire types,
  schemas, inference, joins, or an opinion about what a column means. No Arrow and no Parquet.
- **No global change to `activates`.** Whatever ground-state restoration needs, it is derived where
  it is consumed. `ANCHOR_TIMING`, `WORLD_TIMING` and `anchor.ts` are not touched, and a fourth
  number in the activation model stays parked as idea:20 unless this round produces evidence that
  what would be shared is real rather than nominal.
- **No caching, still.** idea:22 stays parked; a rerun always runs.
- **No relaxation of the exhibit boundary.** No `image:` key, no `data:` key, no path to a
  checked-in CSV, no way to get an artifact that was not computed on this run. One output per slide.
- **No chart library and no table query language.** cuecraft learns what a *row* is, because it is
  laying one out; it does not learn what the data means.
- **No arbitrary CSV.** Documented limits, refused loudly, in preference to a renderer that tries to
  make every possible file look good.

## Outcome

**Both halves landed, and `out/pivot.mp4` is 2:11.9 of them.** R named the sixteen bars it drew and
narration lit four of them one at a time; R pivoted 673 transactions into 24 rows and cuecraft laid
the table out, generated an identity for every row, and — asked for the fifteenth of them in a
window showing six — went and got it.

### The round began from a false premise, and correcting it was the first finding

The brief said semantic SVG was already underway. It was not: `idea:24` was parked, and parked on
`decision:57`'s spike, which found that base R's `svg()` emits no `id` outside `<defs>`, no grouping
and no `<text>`, and concluded that **"addressing needs the program to declare it whichever format
carries the picture"**. That is why regions exist at all.

The conclusion is right about the *device* and wrong about the *program*, and the gap is one
sentence: **a program knows which object it just drew.** cairo writes one `<path>` per drawing call
with the fill it was given, so a call made in a colour nobody else uses is findable in the program's
own output afterwards. Twelve lines of base R, no package (decision:59). A whole design was parked on
a finding that was true and did not mean what it was taken to mean, which is the most useful thing
this round learned about its own archaeology.

### What the exhibit boundary turned out to be

decision:55 defines an exhibit as content cuecraft *cannot read*. Every refusal in it — no `image:`
key, no checked-in asset, no fallback — is actually about **pixels**: a picture that could be stale,
hand-edited, or committed. None of those survives the artifact being a CSV a program computed on this
run. So the boundary was never "content cuecraft cannot understand"; it is **content cuecraft did not
compute**, and the picture was only the first instance of it (decision:60).

That reframing is what let a table be an exhibit rather than a twelfth body, and it cost no new
vocabulary except `key:`.

### The bit that is actually new

    - speech: "South's Ember line is further down still, and it more than quadrupled."
      activates: row-south-ember

The row is fifteenth of twenty-four and six fit. The table moves its viewport by the least it can,
brings the row into view, emphasises it, and lets it go. **Nothing in the deck says to scroll and
there is no key that could.** The position on a frame is folded over the narration's *claims* rather
than over the frames, so it is pure: a still at frame 900 is the same still whether it was rendered
alone or after 899 others.

### Ground state, and why it is a tautology rather than a promise

The invariant asked for was that an emphasized element can return **exactly** to what was imported.
Every mechanism-shaped answer — remember the fill, override it, put it back — has a place where the
restoration can be incomplete, and the incompleteness is silent.

So there is no mechanism: **the markup is never modified.** It is inlined once and emphasis is a
stylesheet computed from the frame number. At zero strength no rule is emitted, so the element is
byte for byte what cairo wrote. `attentionAt` returns `undefined` rather than a zero for exactly this
reason, and the drawing tests assert the absence of a rule rather than the smallness of one.

That also *forced the vocabulary*. cuecraft knows a named element's name and nothing else — not its
fill, not its shape — so the treatment has to compose with an unknown original: multiplicative terms
that are the identity at zero. decision:55's boundary picked the mechanism, which is good evidence
the boundary is real rather than nominal.

`{A,B}` → `{B,C}` needed no special case. Strength comes from the *run*, which merges when a release
is interrupted, so an element's emphasis is continuous across a handover; what travels is *which*
element is lifted, and the two shares sum to one at every frame.

### `activates:` did not change, and that was the interesting constraint

No global semantics moved. `ANCHOR_TIMING`, `WORLD_TIMING` and `anchor.ts` are untouched, eleven
archetypes are identical, and the revenue deck renders as it did.

What happened instead is that decision:58's occupancy — local to the chart for two rounds — got its
second and third callers, so `idea:20`'s test could finally be run. The answer is still **no**: what
three consumers share is an *envelope over intervals*, not a quantity elements carry. That moved to
`render/attention.ts` and read by the exhibit family; `render/exhibit.ts` is now one function, a
rectangle travelling between two rectangles, which is the honest measure of how much of decision:58
was ever about charts (decision:61).

Row **and** column activation — the stretch goal — fell out of that for nothing: two independent
tracks, exclusive within each, so the cell they cross is the answer to both sentences with no
selection algebra and without `activates:` learning to take a list.

### What the artifacts corrected

Five things, and only one of them was found by a test.

- **The drawing receded the wrong set.** Emphasis was applied over `shows:` — the four bars the deck
  talks about — leaving the other twelve at full brightness beside the one being emphasized. The
  frame said "these thirteen matter". A resource now carries *addressable* and *drawn* separately.
- **The picture came out at three quarters of the room**, twice, for two different reasons. First a
  wrapper whose width was defined in terms of an `<svg>` sized at 100% of it; then, after overriding
  the svg to `width:auto`, a replaced element with a ratio and no intrinsic size. **Take the size cairo
  wrote, do not replace it.**
- **The bidirectional `shows:` check was wrong for generated names.** decision:57 refuses a mismatch
  in both directions, which is right when a program hand-writes four region lines and wrong when it
  tags sixteen bars or produces twenty-four rows. Split: *scarce and authored* is checked both ways,
  *generated from content* one way. The half that stops a highlight landing on nothing is untouched.
- **The column floor widened columns instead of only limiting how far they shrank**, so a squeeze
  could add width overall. Found by a property test asserting the columns fit in the room.
- **The deck asserted "of which seven fit" and six fit.** Removed rather than corrected: the register
  already draws "rows 11–16 of 24" from the same viewport the rows come from, and an authored count
  beside a derived one is dragon:16.

### Against the success criteria

Met: `csv` and `svg` are accepted types validated to the bytes with every existing guarantee, tested
with no R installed; SVG identities are discovered from the file rather than declared beside it;
`activates:` reaches a named element and it returns to ground, with sequential and overlapping
attention both ending at ground and no flash through it; a CSV renders as a measured, bounded table
with identities generated from data; an offscreen row is revealed deterministically with nothing
authored saying so; the showcase renders end to end and was judged on the film. `npm run check` 851,
`npm run test:r` 13, `scarp doctor` clean.

**Not met, and deliberately.** The adversarial *wrapping* case is exercised by tests and not by the
film. The reason is a property of the fitter rather than an omission: it sets a table as large as it
can and widens a column to hold its longest value, so nothing wraps until the content cannot fit at
the smallest size on the ladder — which for six columns takes a cell past about 105 characters, and
a table set at 20px to show it. The showcase keeps a 46-character prose column, legible at 30px, and
`register.test.ts` carries the 4,000-character cell. What the film does prove is the *bound*: nothing
overruns, because a row's height is computed from the worst cell before anything is drawn.

### What was refused and stayed refused

No selector syntax, in any form — no `#id=`, no predicate, no CSS, no SQL, no column expression. No
sorting, filtering, editing, conditional formatting, pagination, virtual scrolling or interaction. No
dataframe abstraction: cuecraft parses a CSV into strings and does not know a column is numeric — the
one inference it makes is a text alignment. No Arrow, no Parquet. No cache (idea:22). No `data:` key,
no checked-in artifact, still one output per slide, and a test fails if anything renderable appears in
`examples/pivot/`. No fourth number in the activation model (idea:20). No shared R library, which is
the duplication dragon:35 now watches.

### What this cost

A long cell is expensive for **every** row: the height comes from the worst cell in the table, which
is what makes "reveal row 73" a multiplication rather than a running sum. The showcase pays a third
of its viewport for one prose column (dragon:34). And the technique that names an SVG element lives
in the deck's R program and depends on an implementation detail of cairo's output, so a second deck
copies twelve lines that could break independently (dragon:35).
